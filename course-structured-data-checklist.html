Course structured data checklist

Prelaunch QA for Course list schema and catalog pages.

Use this checklist before publishing course catalog summary pages, bootcamp cohort pages, continuing education catalogs, or LMS template changes.

1. Confirm the page is a real course catalog

  • The page represents educational content with curriculum, lessons, modules, or a clear learning outcome.
  • It is not a general webinar, event page, coupon page, blog article, or thin lead magnet.
  • The visible catalog cards match the courses represented in JSON-LD.
  • The page type decision is clear: summary page, all-in-one list page, or detail page paired with a summary list.

2. Check course count and ItemList wiring

  • Course list pages represent at least three courses when using the course list pattern.
  • The page includes an `ItemList` when the summary/list page needs list markup.
  • Each `ListItem` has a `position` value.
  • Each item has a unique course URL.
  • List order in JSON-LD matches the visible catalog order or has a documented reason.

3. Check Course fields

  • Each `Course` has a neutral `name`.
  • Each `Course` has a useful `description` that explains the course or learning outcome.
  • Descriptions are not empty, duplicated, or only marketing slogans.
  • Course titles do not include discounts, prices, or promotional phrases.

4. Check provider consistency

  • Provider names match the visible course catalog or institution owner.
  • Provider values are not blank on some courses.
  • Provider naming is consistent across LMS templates, catalog cards, and JSON-LD.
  • Multi-campus or multi-brand catalogs have an owner decision for provider naming.

5. Check URL and canonical drift

  • Each course URL points to the current public course detail or catalog destination.
  • Old cohort URLs are removed from current catalog markup.
  • Duplicate course URLs are resolved.
  • Visible course-card links, canonical URLs, and JSON-LD URLs agree.

6. Assign remediation owners

  • LMS owner confirms source fields.
  • Course marketing confirms visible titles and descriptions.
  • Catalog or frontend owner confirms list rendering and canonical links.
  • SEO owner confirms final markup handoff.
  • No launch proceeds with owner fields marked TBD.

7. Keep public handoffs safe

  • Do not paste private student data, LMS exports, credentials, or enrollment data into public issues.
  • Use anonymized Course/ItemList snippets for public demo requests.
  • Treat this checklist as technical SEO launch QA, not education compliance, accreditation, ranking, indexing, or student-support advice.
